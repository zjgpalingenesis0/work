# 1. 两数之和

- LeetCode：[1. 两数之和](https://leetcode.cn/problems/two-sum/)
- 难度：简单

## 先理解题意

从数组中找到两个不同位置的数字，使它们的和等于 `target`，然后返回这两个数字的下标。

例如：

```text
nums = [2, 7, 11, 15]
target = 9
```

因为：

```text
nums[0] + nums[1] = 2 + 7 = 9
```

所以返回：

```text
[0, 1]
```

题目要求返回下标，不是返回数字 `[2, 7]`。

## 解题思路

遍历到当前数字 `number` 时，需要寻找另一个数字：

```text
needed = target - number
```

这个 `needed` 可以称为当前数字的补数。

例如：

```text
target = 9
当前数字 = 7
needed = 9 - 7 = 2
```

如果之前已经见过数字 `2`，就找到了答案。

因此可以一边遍历，一边使用 `Map` 保存之前见过的数字及其下标：

```text
数字 -> 下标
```

## 用到的数据结构及原因

### `Map`（哈希表）

保存：

```text
之前出现过的数字 -> 该数字的下标
```

选择 `Map` 的原因：

1. 可以平均 `O(1)` 地判断补数是否已经出现。
2. 可以平均 `O(1)` 地取得补数对应的下标。
3. 数字可能是负数，使用 `Map` 不受普通数组下标限制。

如果使用两层循环枚举所有数字组合，时间复杂度是 `O(n²)`；使用 `Map` 可以降低到 `O(n)`。

## 用到的方法及原因

### 一次遍历

从左向右遍历数组。对于每个数字：

1. 计算它需要的补数。
2. 检查补数是否已经存在于 `Map`。
3. 如果存在，直接返回两个下标。
4. 如果不存在，把当前数字和下标加入 `Map`。

### `map.has(key)`

判断补数是否已经出现过。

应该使用 `has()`，不能只根据 `get()` 的返回值真假判断，因为合法下标可能是 `0`，而 `0` 在 JavaScript 中是假值。

### `map.get(key)`

取得补数之前出现时的下标。

### `map.set(key, value)`

保存当前数字和它的下标：

```text
map.set(当前数字, 当前下标)
```

## 为什么先查询，再保存当前数字

题目要求使用两个不同位置的元素。

例如：

```text
nums = [3, 2, 4]
target = 6
```

遍历第一个 `3` 时，如果先把它存入 `Map`，再查找补数 `3`，就可能错误地让同一个下标与自己配对。

正确顺序是：

```text
先查询之前是否有补数
再保存当前数字
```

这样查到的下标一定来自当前下标之前，不会使用同一个元素两次。

对于 `[3, 3]`，处理第一个 `3` 时查不到补数，然后保存它；处理第二个 `3` 时就能找到第一个 `3`，因此仍然可以正确返回 `[0, 1]`。

## 过程示例

输入：

```text
nums = [2, 7, 11, 15]
target = 9
```

处理下标 `0`：

```text
当前数字 = 2
需要的补数 = 9 - 2 = 7
Map 中没有 7
保存 2 -> 0
```

此时：

```text
Map = { 2 -> 0 }
```

处理下标 `1`：

```text
当前数字 = 7
需要的补数 = 9 - 7 = 2
Map 中存在 2，对应下标 0
```

所以返回：

```text
[0, 1]
```

## 伪代码

```text
创建空 Map

从左向右遍历 nums：
    number = 当前数字
    needed = target - number

    如果 Map 中存在 needed：
        返回 [needed 对应的下标, 当前下标]

    将 number 和当前下标存入 Map
```

## JavaScript 代码

```js
/**
 * @param {number[]} nums
 * @param {number} target
 * @return {number[]}
 */
var twoSum = function (nums, target) {
  const indexByNumber = new Map();

  for (let i = 0; i < nums.length; i++) {
    const number = nums[i];
    const needed = target - number;

    if (indexByNumber.has(needed)) {
      return [indexByNumber.get(needed), i];
    }

    indexByNumber.set(number, i);
  }
};
```

## 复杂度分析

设数组长度为 `n`：

- 时间复杂度：`O(n)`。只遍历数组一次，`Map` 查询和更新平均为 `O(1)`。
- 空间复杂度：`O(n)`。最坏情况下需要在 `Map` 中保存接近所有元素。

## 容易出错的地方

### 1. 返回数字而不是下标

题目需要返回：

```text
[补数的下标, 当前数字的下标]
```

而不是 `[needed, number]`。

### 2. 用 `map.get()` 的真假判断是否存在

下面的写法有问题：

```js
if (indexByNumber.get(needed)) {
```

如果补数位于下标 `0`，`get()` 返回 `0`，条件会被判断为假。应该使用：

```js
indexByNumber.has(needed)
```

### 3. 先保存当前数字，再查询补数

这样在 `number * 2 === target` 时，可能使用同一个元素两次。应该先查询，再保存。

### 4. 使用两层循环

两层循环可以得到正确答案，但时间复杂度是 `O(n²)`。哈希表能把查找补数的过程降为平均 `O(1)`。

### 5. 不理解重复数字如何处理

`Map` 保存数字到下标的映射。因为每轮先查询再保存，所以 `[3, 3]`、`target = 6` 能正确使用两个不同下标。

### 6. 没有显式返回未找到结果

题目保证恰好存在一个答案，所以循环结束前一定会返回。在通用函数中，可以根据需求额外返回空数组或抛出错误。
