# 88. 合并两个有序数组

- LeetCode：[88. 合并两个有序数组](https://leetcode.cn/problems/merge-sorted-array/)
- 难度：简单

## 解题思路

`nums1` 的前 `m` 个元素和 `nums2` 的前 `n` 个元素分别已经升序排列，并且 `nums1` 的总长度是 `m + n`，末尾预留了放置 `nums2` 的空间。

例如：

```text
nums1 = [1, 2, 3, 0, 0, 0]，m = 3
nums2 = [2, 5, 6]，n = 3
```

如果从前往后写入 `nums1`，较小元素可能会覆盖 `nums1` 中还没有参与比较的有效元素。

因此应该从后往前合并：

1. `i` 指向 `nums1` 有效部分的最后一个元素。
2. `j` 指向 `nums2` 的最后一个元素。
3. `write` 指向 `nums1` 最后一个可写位置。
4. 比较 `nums1[i]` 和 `nums2[j]`，把较大的元素写到 `nums1[write]`。
5. 对应指针向前移动，直到 `nums2` 的元素全部放入 `nums1`。

## 用到的数据结构及原因

### 输入数组 `nums1` 和 `nums2`

不需要额外数组，直接利用 `nums1` 末尾预留的 `n` 个位置完成原地合并。

这样做的原因：

1. `nums1` 已经提供了容纳全部元素的空间。
2. 从后向前写入不会覆盖尚未处理的有效元素。
3. 额外空间复杂度可以保持为 `O(1)`。

### 三个下标指针

- `i = m - 1`：指向 `nums1` 有效部分当前最大的元素。
- `j = n - 1`：指向 `nums2` 当前最大的元素。
- `write = m + n - 1`：指向 `nums1` 当前应该写入的位置。

使用三个下标的原因是，需要分别记录两个数组的读取位置和结果数组的写入位置。

## 用到的方法及原因

### 逆向双指针

两个读取指针分别从两个有序数组的末尾开始，比较当前最大的两个元素。

选择逆向双指针的原因：

1. 两个数组已经有序，末尾元素就是各自尚未处理部分的最大值。
2. `nums1` 的空闲空间位于末尾，适合从后向前填充。
3. 每个元素最多处理一次，时间复杂度为 `O(m + n)`。
4. 不需要额外结果数组。

## 过程示例

初始状态：

```text
nums1 = [1, 2, 3, 0, 0, 0]
                 i        write

nums2 = [2, 5, 6]
              j
```

比较 `3` 和 `6`，将 `6` 放到最后：

```text
[1, 2, 3, 0, 0, 6]
```

比较 `3` 和 `5`，将 `5` 放到倒数第二位：

```text
[1, 2, 3, 0, 5, 6]
```

比较 `3` 和 `2`，将 `3` 放入：

```text
[1, 2, 3, 3, 5, 6]
```

继续比较并写入，最终得到：

```text
[1, 2, 2, 3, 5, 6]
```

## 伪代码

```text
i 指向 nums1 有效部分末尾，即 m - 1
j 指向 nums2 末尾，即 n - 1
write 指向 nums1 整体末尾，即 m + n - 1

当 j >= 0：
    如果 i >= 0，并且 nums1[i] 大于 nums2[j]：
        将 nums1[i] 写入 nums1[write]
        i 向前移动
    否则：
        将 nums2[j] 写入 nums1[write]
        j 向前移动

    write 向前移动
```

## JavaScript 代码

```js
/**
 * @param {number[]} nums1
 * @param {number} m
 * @param {number[]} nums2
 * @param {number} n
 * @return {void} Do not return anything, modify nums1 in-place instead.
 */
var merge = function (nums1, m, nums2, n) {
  let i = m - 1;
  let j = n - 1;
  let write = m + n - 1;

  while (j >= 0) {
    if (i >= 0 && nums1[i] > nums2[j]) {
      nums1[write] = nums1[i];
      i--;
    } else {
      nums1[write] = nums2[j];
      j--;
    }

    write--;
  }
};
```

## 为什么只需要判断 `j >= 0`

循环只要求 `nums2` 还有未处理元素：

```text
j >= 0
```

原因分为两种情况：

1. 如果 `nums2` 先处理完，`nums1` 剩余元素本来就在正确位置，不需要移动。
2. 如果 `nums1` 先处理完，循环会继续执行，把 `nums2` 剩余元素依次复制到 `nums1` 前面。

因此不需要在主循环后单独处理 `nums1` 的剩余元素。

## 复杂度分析

- 时间复杂度：`O(m + n)`。两个数组中的每个元素最多处理一次。
- 空间复杂度：`O(1)`。只使用三个下标变量，并直接修改 `nums1`。

## 容易出错的地方

### 1. 从前向后写入

从前向后写可能覆盖 `nums1` 中尚未比较的有效元素。使用额外数组可以从前向后处理，但如果要求原地合并，应从后向前写。

### 2. `i` 的初始值写成 `nums1.length - 1`

`nums1` 后面的 `n` 个位置只是预留空间，不属于原有有效元素。因此 `i` 应该从：

```text
m - 1
```

开始，而不是从 `nums1.length - 1` 开始。

### 3. `write` 的初始值少减一

数组最后一个下标是：

```text
m + n - 1
```

### 4. 忘记处理 `nums1` 有效部分为空的情况

当 `m = 0` 时，`i = -1`。条件中的 `i >= 0` 会失败，程序会把 `nums2` 的所有元素复制到 `nums1`。

### 5. 返回了一个新数组

题目要求直接修改 `nums1`，不需要返回合并后的数组。
